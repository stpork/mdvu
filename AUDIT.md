# Аудит mdvu — 15 сентября 2026

Проверены Swift-код приложения, JavaScript/CSS, загрузка документов, навигация, управление окнами и ресурсами, тесты и пути релизной сборки. Исправления сохраняют функции приложения и существовавшие пользовательские изменения. Это аудит конкретной версии и сценариев, не доказательство отсутствия всех возможных ошибок.

## Пять основных исправленных багов

| Приоритет | Проблема и воспроизведение | Причина и исправление |
|---|---|---|
| P1 | Автообновление переставало работать: удалить/переименовать открытый файл, вернуть его спустя более 350 мс, затем изменить. | `FileWatcher` делал только две попытки повторного подключения. Более того, преждевременный callback мог заменить watcher до восстановления файла. Теперь повторные попытки продолжаются до восстановления/отмены; уведомление приходит после подключения. Состояние и события перенесены на одну main queue. |
| P1 | При переходе A → B → «Назад» терялась позиция A; запоздавший callback мог добавить старую страницу после более нового перехода. | В `openDocument` сначала добавляли B, затем повторно вызывали `push(B, ratio)`, который игнорировал позицию как дубликат. Теперь callback обновляет позицию предыдущей записи, не добавляя переход. |
| P1 | После закрытия окна могли выполняться уже поставленные в очередь загрузки/действия WebView. | Одной отмены `Operation` недостаточно для уже отправленных callbacks. `tearDown` стал идемпотентным, инвалидирует поколение загрузки, отменяет поиск, останавливает WebView и отключает delegate. Запоздавшие render/runtime callbacks проверяют актуальность; callback обхода каталога проверяет отмену. |
| P2 | Один клик в навигаторе мог дважды прочитать, преобразовать и загрузить документ. | Одновременно работали action клика и delegate изменения выделения. Удалён лишний action; клавиатура и выбор файла сохранены. |
| P2 | `[TOC]` и `[[_TOC_]]` внутри fenced code превращались в разметку оглавления и портили пример кода. | TOC-преобразование теперь использует общий сканер fenced blocks. Регрессионный тест одновременно проверяет литералы внутри блока и работающий TOC снаружи. |

Код: `Sources/mdvu/UI/FileWatcher.swift`, `Sources/mdvu/UI/DocumentWindowController.swift`, `Sources/mdvu/UI/VaultNavigator.swift`, `Sources/mdvu/Markdown/MarkdownPipeline.swift`.

Дополнительно исправлено ожидание асинхронного рендеринга: native bridge теперь использует `callAsyncJavaScript` с `await`, а не считает возвращённый Promise завершённой работой. Итоговая визуальная проверка Universal после этого прошла с RMS 0,00000; до исправления один прогон давал 0,04666.

Исправлены также два дефекта JavaScript:

- Заголовки `A`, `A`, `A-1` получали одинаковые ID. Теперь ID уникальны, поэтому якорь ведёт к нужному заголовку.
- Поиск вычислял позиции в строке после `toLocaleLowerCase()`, которая может изменить длину Unicode-текста. Например, поиск `target` после `İstanbul` выделял неверный диапазон. Теперь поиск использует индексы совпадений в исходной строке; спецсимволы запроса экранированы. Проверено в WKWebView, включая `a.b`, `a+b`, `[x]` и восстановление текста после очистки поиска.

## Пять архитектурных проблем

1. **Контроллер окна объединяет слишком много обязанностей.** Более 2000 строк: UI, history, filesystem, парсинг, HTML-файлы, JS bridge, zoom, snapshots. Это затрудняет единое управление жизненным циклом. Частично исправлено общей отменой и единым helper загрузки runtime. Следующее оправданное разделение — `DocumentLoadCoordinator` и `WebRuntimeLoader`; массовое механическое разбиение сейчас не делалось.
2. **Несколько независимых сканеров Markdown.** Obsidian, admonitions, math, critic/sub/sup и TOC имеют разные правила обработки fenced/inline кода и последовательно создают строки. Это источник расхождений и лишних проходов. TOC переведён на общий сканер. Остальное следует переводить на общие диапазоны защищённого кода с тестами совместимости; например, inline code пока защищён не одинаково во всех extensions.
3. **Два пути подготовки документа: eager `Task` и обычная `OperationQueue`.** Они повторяют чтение, выбор параметров и передачу результата. Eager-путь отдельно предполагает light для system theme, что требует дополнительной проверки кешированных диаграмм в тёмной теме. Следует сохранить ранний запуск ради скорости, но использовать общий render request с theme/options/generation и общей отменой. Полное объединение не выполнено.
4. **Два механизма просмотра каталога и разная политика ресурсов.** Рекурсивный список в контроллере и lazy tree в `VaultNavigator` имеют разные правила исключения; tree читает filesystem синхронно из UI callbacks и не обновляет уже закешированные children автоматически. Общий асинхронный directory service с инвалидируемыми snapshot уменьшит дублирование и задержки на медленных дисках. Устранена двойная загрузка по клику; перенос сканирования требует отдельной проверки корректности NSOutlineView.
5. **Расходящиеся настройки сборки.** Локальный релиз использовал `-O`, CMO и dead stripping; Universal — отдельный набор с `-Osize`. Производительность установленного релиза могла отличаться от локальных измерений. Теперь Universal получает флаги из Makefile через `print-release-flags`, а безусловный clean убран. Это сокращает повторные сборки и исключает дрейф конфигурации.

Дополнительно удалены неиспользуемые Swift API рендеринга диаграмм, которые всегда бросали `webRuntimeRequired`, и неиспользуемый regex. Реальный рендеринг остаётся в WebView. Кеш SVG в памяти теперь общий для окон, как уже был общий кеш на диске.

## Производительность и размер

Сохранены предварительная обработка первого документа, предварительный прогрев WebView и автоматическое создание резерва для следующего окна. Резерв — сознательный компромисс скорости и памяти, не установленная утечка. Его удаление было отменено; отдельного A/B-измерения следующего окна не проводилось.

Распаковка Mermaid/PlantUML/KaTeX перенесена с main queue в background queue. Результаты по-прежнему кешируются, а установка JavaScript в WKWebView выполняется на main queue с проверкой поколения документа. Это устраняет источник блокировки UI, не обещая конкретного выигрыша FPS без замеров кадров.

Локальная arm64-сборка — около **3,4 MiB на диске**, из них Mermaid и PlantUML занимают около 2,54 MiB в уже сжатом виде. Исполняемый файл итоговой `-O` сборки — **719 296 байт**. Вариант `-Osize` — **690 104 байта**: экономия 29 192 байт, менее 1% приложения. В прогоне `-Osize` парсинг был медленнее, поэтому сохранён `-O`. В первоначальном сравнении с промежуточной сборкой разница составляла 15 КБ; итоговое сравнение выше точнее.

Медианы пяти запусков после прогрева; стандартный `scripts/benchmark.sh`:

## Память, процессы и границы проверки

- Кеш SVG больше не размножается по одному на окно: общий `NSCache` с cost limit 16 MiB и count limit 128. Лимиты NSCache рекомендательные, а не жёсткая гарантия потребления; UTF-8 cost также не равен полному footprint объектов.
- Отмена watcher/render/search и поколение загрузки проверены; существующий тест освобождения контроллера проходит.
- CLI benchmark для `test-heavy.md` (1,58 MiB): медиана 115,25 мс, maximum RSS 33 947 648 байт. Это отдельный процесс парсера, не GUI.
- Живое окно `test-complete.md`: footprint основного процесса 76,8 → 77,1 MiB, пик 79,1 MiB. Два запуска `leaks` дали одинаковые **285 объектов / 14 272 байта**, с основными корнями AppIntents/XPC. macOS предупредила, что процесс не debuggable и чтение памяти ограничено. Поэтому это не доказательство отсутствия собственных утечек и не основание утверждать, что всё показанное точно принадлежит системе.
- В этих значениях не суммированы отдельные процессы WebKit. Длительный стресс открытия/закрытия, измерения кадров прокрутки/зума, Instruments Allocations/Leaks и наблюдение за завершением всех дочерних процессов не проведены.
- Дисковый кеш диаграмм пока не имеет eviction policy. Распакованные runtime-строки удерживаются статическими свойствами после первого использования ради повторной загрузки. Navigator хранит посещённые ветви дерева. Это ограничиваемые/управляемые ресурсы, которые следует отдельно профилировать, а не автоматически считать утечками.
- Raw HTML обрабатывается с `CMARK_OPT_UNSAFE`; tagfilter не равнозначен полноценной изоляции активного HTML. Проверка безопасности произвольных документов требует отдельного рассмотрения, особенно вместе с широким доступом WebView к локальным ресурсам.

## Проверки

- `make test`: **60/60**, включая новые проверки watcher, history, TOC и реального JS runtime.
- `make visual-test`: **passed**, normalized RMS **0,00000** с существующим эталоном. Один промежуточный прогон при одновременных GUI-проверках дал отличие 0,16328; после прекращения конкурентных GUI-проверок повтор прошёл. Порог и эталон не изменялись этим аудитом.
- В DOM-тесте offscreen WKWebView animation-frame scheduling заменён таймером: тест проверяет корректность DOM, а не FPS.
- Визуальная проверка собранного Universal: **passed**, normalized RMS **0,00000**; результат сохранён в `Tests/Audit/universal-visual.txt`.
- `node --check Sources/mdvu/Resources/app.js`: passed.
- `make universal`: обе архитектуры arm64 и x86_64 успешно собраны; Universal app занимает около **4,2 MiB**, ресурсы в нём не дублируются.
- `make app`: релиз собран и подписан ad hoc. Проверены существующие тесты zoom, menus, layout, lifecycle. Они не заменяют измерения жестов на устройствах и кадров UI.

Дальнейшая работа с наибольшей ожидаемой пользой: измерение frame time на больших документах, перенос directory I/O с UI, единая отменяемая загрузка документа и ограничение дискового кеша. Абсолютный минимум размера, предельная скорость и отсутствие всех утечек не установлены этим аудитом.
